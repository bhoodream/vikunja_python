# Самостоятельная разработка Vikunja CLI: Обучающий материал

Этот гайд поможет вам разобраться, как устроено созданное приложение, и закрепить навыки разработки CLI-инструментов на Python.

## 1. Архитектура приложения

Приложение построено на трех "китах":

1. **Интерфейс (Click)**: Обработка аргументов командной строки и переменных окружения.
2. **Связь (Requests)**: Взаимодействие с внешним API через HTTP.
3. **Визуализация (Rich)**: Форматирование данных в красивые таблицы и панели.

### Ключевые принципы (Clean Code):

- **Single Responsibility**: Каждый метод делает что-то одно (запрос данных, форматирование даты, проверка просрочки).
- **Fail Fast**: Если API недоступно, программа сразу сообщает об этом и завершается, а не пытается работать с пустыми данными.
- **Fallback Strategy**: Если один эндпоинт (`/tasks/all`) не работает, программа переключается на другой (запрос по проектам).

## 2. Разбор ключевых компонентов

### Работа с API

Мы создали класс `VikunjaClient`. Это позволяет инкапсулировать (спрятать) детали авторизации и базовый URL внутри объекта.

```python
class VikunjaClient:
    def __init__(self, url, token):
        self.headers = {"Authorization": f"Bearer {token}"}
        # ...
```

### Обработка дат

Vikunja присылает даты в формате ISO 8601 (например, `2024-04-21T12:00:00Z`). Для работы с ними в Python мы использовали `datetime.fromisoformat`.
*Важно*: Символ `Z` в конце означает UTC. В старых версиях Python его нужно заменять на `+00:00`.

### CLI и переменные окружения

Использование `envvar` в `click.option` — это лучший способ сделать инструмент удобным:

```python
@click.option('--token', envvar='VIKUNJA_TOKEN')
```

Это позволяет пользователю не вводить токен каждый раз, а просто положить его в `.env`.

## 3. Упражнения для закрепления

Чтобы почувствовать себя автором проекта, попробуйте выполнить следующие задачи:

### Упражнение 1: Фильтрация задач

Сейчас программа выводит **все** задачи. Добавьте флаг `--only-open`, который будет скрывать уже выполненные задачи.
*Подсказка*: В цикле перебора задач добавьте проверку `if task.get('done') and only_open: continue`.

### Упражнение 2: Сортировка

Сделайте так, чтобы задачи внутри проекта были отсортированы по дате дедлайна (сначала самые срочные).
*Подсказка*: Используйте `sorted(project_tasks, key=lambda x: x.get('due_date') or '9999')`.

### Упражнение 3: Статистика

В конце вывода добавьте общую сводку: сколько всего задач, сколько из них просрочено и сколько выполнено.
*Подсказка*: Создайте счетчики перед циклом и инкрементируйте их.

## 4. Чек-лист для будущих проектов

Когда будете делать свой следующий CLI-инструмент, следуйте этому плану:

1. [ ] Создай `requirements.txt` и виртуальное окружение.
2. [ ] Создай `.env.example`.
3. [ ] Напиши минимальный клиент для API (проверь связь).
4. [ ] Добавь `click` для обработки аргументов.
5. [ ] Добавь `rich` для красоты, когда логика уже работает.
6. [ ] Напиши `.gitignore`, чтобы не "слить" ключи.
